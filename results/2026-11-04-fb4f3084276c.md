# Competitor benchmark results

Method: criterion 0.5, 3 s measurement, 1 s warm-up, 100 samples
(spec section 11.3), pinned with `taskset -c 3`.

## Note

The run started on a quiet machine (no fuzzers, load average 0.21 in the
first minute), but its drift control moved in the first workload: in the
`h1_head_simd` pass the `http_net/parse_request_head` rows came out 5 to
9% above the same rows in `h1_head_nosimd`, which they must not be, since
http-net does not use httparse. Every later control agrees within 2% (H3 http-net rows,
`server_conn_head`).

So H1 was run again on its own straight after, from the same two
binaries, both modes twice, alternating (load average 0.72 at start, 1.00
at end). In those four passes http-net agrees with itself across modes
within 1%. Read H1 from this table, not from the `h1_head_*` rows below.
Times are criterion's middle estimate, pass 1 / pass 2:

| Row | `h1_head_simd` | `h1_head_nosimd` |
|---|---:|---:|
| `http_net/parse_request_head/16` | 173.0 / 173.6 ns | 173.4 / 173.4 ns |
| `http_net/parse_request_head/32` | 173.5 / 173.7 ns | 172.2 / 173.2 ns |
| `http_net/server_conn_head` | 185.7 / 184.6 ns | 186.2 / 187.3 ns |
| `httparse/parse_and_framing/16` | 168.6 / 176.4 ns | 153.4 / 152.6 ns |
| `httparse/parse_and_framing/32` | 173.1 / 178.8 ns | 153.6 / 155.3 ns |
| `httparse/parse_only/16` | 112.9 / 114.4 ns | 99.3 / 99.1 ns |
| `picohttpparser/parse_and_framing/16` | 157.9 / 157.7 ns | 155.0 / 158.4 ns |
| `picohttpparser/parse_only/16` | 102.2 / 103.8 ns | 102.5 / 100.6 ns |
| `picohttpparser_scalar/parse_and_framing/16` | 165.2 / 164.0 ns | 154.3 / 155.3 ns |
| `picohttpparser_scalar/parse_only/16` | 111.1 / 110.2 ns | 98.4 / 98.2 ns |

The picohttpparser rows do not use httparse either, yet the scalar copy
is 6 to 12% slower in the SIMD-on binary than in the SIMD-off one, in the
full run and in both passes alike, while http-net does not move. The C
code is compiled the same way for both; what differs is the Rust around
it, which fat LTO lays out anew for each binary. Compare picohttpparser
rows within one binary only. Within either, the SSE4.2 build gains at
most 4% on this head (lines of about 30 bytes), and httparse's SIMD path
loses to its own scalar path.
